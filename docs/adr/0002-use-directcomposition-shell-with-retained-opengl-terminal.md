# Use a DirectComposition shell with the retained OpenGL terminal

koreterm will replace GDI application chrome incrementally with a native DirectComposition, Direct2D, and DirectWrite shell while retaining the proven WGL/OpenGL terminal renderer. The shipped boundary owns recoverable D3D11/DirectComposition targets and transparent DPI-sized surfaces for top-level Host windows. Host banner and operation-feedback text is the first production DirectWrite zone; it falls back to GDI whenever drawing, commit, or device recovery fails. Remaining chrome stays on GDI until it passes the same isolated-zone gates. This isolates shell polish and refresh-aware composition work from Ghostty's terminal rendering pipeline, avoiding the reliability and parity risk of rewriting both stacks at once.

**Update 2026-10-11 (PKG-33).** The shell pipeline is no longer started at launch. Measured on this machine, building the hardware D3D11 device, DirectComposition and DirectWrite resources before the first window added about 156 ms to the time from `main` to the first swap (171 ms from launch), about 54 MiB of private bytes, 79 driver threads and about 79 idle context switches a second, for explicit banner text only. `App.init` now gives the backend no driver, so every host stays on GDI chrome. The device-graph code and its tests remain until the D3D11 renderer decision settles whether it is reused; starting it again needs a consumer that justifies that cost.
