- 2026-10-30: After #609 moved Kitty graphics to WUFFS (#570), the updater still decoded with Zig 0.15.2's std flate twice. The async WinHTTP transport (PKG-62) sent `Accept-Encoding: gzip, deflate, identity` itself and decoded through `std.http.Decompress`, and `std.zip.extract` inflated portable update ZIPs. Requests now send `Accept-Encoding: identity`, and every body the updater reads refuses any other coding in any `Content-Encoding` field (`requireIdentityEncoding`, which follows the `WinHttpQueryHeaders` index). That covers `Response.streamBody` for API and asset bodies and `Response.discardBody` for the redirect bodies `fetchHttps` drops; a first draft drained redirects with `Response.read` and missed them. `extractPortableZip` replaced `std.zip.extract`, with WUFFS raw deflate in `pkg/wuffs/src/deflate.zig`. It keeps every check of std's `Entry.extract`, including the local extra-field framing that a first draft dropped. It adds an exact-size and CRC-32 check for file entries, which it decodes, and checks directory entries only by their declared metadata (size 0, CRC-32 0); like std, it does not decode a directory's stored bytes. Five traps. (1) `std.zip.extract` has two crash paths on 0.15.2, not one. The first is #570's fixed-Huffman window bug: a ZIP holding #609's `Z_FIXED` fixture panics at `Decompress.zig:404` in ReleaseSafe and segfaults in ReleaseFast. The second hits any malformed deflate entry: flate reports its decode error as `ReadFailed`, and zip.zig then returns `stream.err.?`, the file reader's error, which is null. Measured on a bad-NLEN stored block: ReleaseSafe panics `attempt to use null value`; ReleaseFast returned success with a 0-byte file for a 5-byte entry. std.zip also never checks CRC-32 (`verify_checksums` is `@panic("TODO")`), stops at the declared uncompressed size without noticing more output, and does not bound its input by the compressed size. (2) WUFFS deflate can stream into one reused output buffer only if `dst.meta.pos` holds the stream offset of the buffer's first byte.
