- 2026-10-15: UIA ScrollIntoView uses a pointer-free absolute row and frozen bounded document window, validating and moving under one renderer lock. Viewport-relative hashes reject a range after its own scroll; captured rectangles stay at old locations. Track row provenance independently of viewport motion. Partial first-page history erasure can preserve page serials while renumbering rows; include structural row generation in geometry and the scroll fingerprint. Row erasure, IL/DL/RI, margin paths and scrolling above a status line must all advance generation before mutation, including partial failures. Screen replacement is separate: RIS destroys the alternate PageList, and re-entry can repeat all its local counters, even with identical text. Include the existing ScreenSet generation in both checks. Keep session locks out of synchronous sends and retain owned bounded retry work. Publish provenance with matching text/cells only after the last fallible allocation. The visible-range cache can lag live geometry; terminal Select stays rejected. Tab close uses a fragment Button with full close-zone bounds even at zero hover alpha, stable-ID queued invocation through confirmation/undo, hidden-state revalidation and events through events.zig.
- 2026-10-15: UIA providers share typed COM identity/refcount thunks through `win32_uia/object.zig`; recover each interface with its named field offset and retain provider-specific IID eligibility and final release ordering. FrameworkId transfers a fresh BSTR each time. Terminal visible text is a slice of the normalized document range; the session and query paths no longer allocate it separately. A hardcoded caret OOM index stopped failing after removing one allocation, so the test now uses `checkAllAllocationFailures` and checks cleared outputs on every failure. Disconnect retry/latch policies remain unchanged pending per-provider evidence; document/cell snapshot copies remain.
- 2026-10-15: The UIA echo queue (typed characters waiting to be seen echoed, `recent_input` in `win32_terminal_accessibility.zig`) was no longer cleared by a full-screen program once #373 stopped capturing the alternate screen: its redraws used to mismatch the queue, and now nothing reached it, so for up to one second after leaving the alternate screen a primary-screen line that started with the typed characters was stripped as their echo (UIA-ECHO-01). A screen switch (modes 47, 1047, 1049, entered or left) now makes the consumer forget the queue. Rules the review left. (1) The clear must sit at its place in the stream, not before the batch: `SemanticOutputCapture.reset_at` is the byte index of the first switch (0 is the full reset, which also drops what came before) and `TerminalOutputTransport.pushSemanticCapture` pushes the bytes ahead of it, then the rest with the reset. A batch-wide flag cleared the queue ahead of the primary-screen bytes that precede the switch in the same PTY read, which is where the echo of `vim file` sits when it arrives together with `?1049h`, and the first draft's own test asserted that outcome. An empty tail push becomes `trailing_reset`, so the reset still lands between the chunks and before the next batch's data. Only the first switch matters, since nothing is held again until the batch is delivered. (2) Only a switch that changes the active screen counts: `Terminal.switchScreen` returns early when the requested screen is already active, and `StreamHandler.switchScreenMode` compares `screens.active_key` before and after (`restore_mode` reaches it through `setMode` too). (3) Not covered: the user `reset` action and the redo of a reset call `terminal.fullReset()` directly, bypassing the handler's `resetForFullReset`, so with the program on the alternate screen the next primary text can still meet a stale queue. (4) A session-level test that only calls `resetSemanticOutputContinuity` passes without the fix and proves nothing; the test that counts drives capture, transport and session in order (`has_text` on the normalizer shows whether any text survived the echo strip: a line that is exactly the typed text strips to nothing, which is what separates the cases). (5) Harness traps: appending an `inline for` of comptime-string `stream.nextSlice` calls to the long "semantic output capture follows real stream handler parser" test fails the build with `evaluation exceeded 100000 backwards branches` at `src/lib/union.zig:124` (the test body is one comptime budget): give new stream assertions their own test with its own fixture. A heredoc through this agent's Git Bash turned `\\` into `\`, so `\x1b` in a Python string became a raw ESC byte in the Zig source (`string literal contains invalid byte`): write scripts with the file tool.
- 2026-10-15: PKG-55 (UIA terminal text), five traps. (1) `UIA_ToolTipControlTypeId` was 50042 where UIAutomationClient.h says 50022 (50042 is no control type); a diff of every id in `win32_uia/constants.zig` against UIAutomationClient.h and UIAutomationCore.h (`LiveSetting`) found that one mismatch. `constants.zig` now carries a table of the SDK values that a test checks, and the test fails for a declared id that is not in the table, so a new constant has to be pinned when it is added; the table check needs `@setEvalBranchQuota` (59 x 59 inline comparisons exceed the default 1000). The tooltip provider's ControlType is also pinned to the literal 50022 in a widgets test, since asking the constant would agree with a wrong constant. The live tooltip could not be inspected: `presentTooltip` returns unless `GetCursorPos` lies inside the tab, and on a private desktop `GetCursorPos` fails with error 5 (measured, 40 of 40 calls), so a hidden-desktop run can never show a tab or search-button tooltip; only unit tests cover its UIA identity. (2) The spoken-output capture (`SemanticOutputCapture`, fed by `StreamHandler`) took every printed codepoint whatever the screen, so a program on the alternate screen, which repaints by cursor addressing, was announced as its changed cells in write order. `StreamHandler.capturesSemanticOutput` (main status display on the primary screen) now gates print, REP, tab, LF and CR, evaluated per action so a switch inside one PTY batch (47, 1047 and 1049) is honoured and the text before and after it still arrives ("main" + "back" in one batch). Measured on a hidden desktop with a UIA client (`AddAutomationEventHandler` accepts the Notification event id 20035 and counts it; the generic handler cannot read the notification text), bundled ConPTY, debug portable copies of main and the branch, two runs each: 3 lines on the primary screen raised 3 Notification events on both; 40 positioned repaints on the alternate screen raised 40 on main (one per repaint) and 0 on the branch, while TextChanged kept firing there (21-40 events; the UIA client coalesces) and 2 lines after leaving raised 2 on both. With `NOCTTY_CONPTY=inbox` set, the branch also raised 0 for the alternate-screen burst (the in-box stream differed, 3 Notification events for the last 2 lines; the in-box log line was not captured, so that it was the in-box host is inferred from the difference). Not measured: what NVDA or Narrator say about the alternate screen now. Everything run inside tmux or zellij is on the alternate screen and is no longer queued as speech. The echo-suppression queue (`recent_input`) is no longer emptied by a full-screen program's own redraws, so for up to its 1 s window after the last key a primary-screen line that begins with exactly the typed characters is treated as their echo (inferred from the code, not run). (3) `snapshotTerminalAccessiblePlainText` called `PageList.pointFromPin(.screen, pin)` for every byte of the document window while holding the renderer mutex; that call walks from the first page to the pin's page, so a snapshot cost bytes x pages. `ScreenRows` in `win32_uia/text.zig` resolves the first pin and derives later ones from the page they share or follow (a pin from anywhere else walks again, and `walks` counts them). Measured in a Debug test over 173 pages (100,000 printed rows, 41,920 pins of the last 524 rows): 10,368 us per-byte against 236 us, identical rows. `Selection.contains` derives `topLeft` and `bottomRight` on every call (two `order` calls and three more walks, about seven per call, from reading the code), so the rectangle-selection loop in `selectionOffsets` now tests the columns it computed once; the active row is an endpoint's row, hence inside the rectangle's rows. Test traps: `Terminal.printString("...\n")` is a bare LF, so lines staircase and wrap at 80 columns (use "\r\n" when a test counts rows); a page holds 579 rows at 80 columns, and the 10,000,000-byte scrollback limit already pruned a 20,000-row print, so a line's number is not its screen row; the formatter gives the `\n` between two pages the next page's first-row pin, so a test that checks each byte's row must skip it; a rectangle test on one page cannot tell a pin's own `y` from its screen row (a mutant using `pin.y` passed the old test and fails the later-page one). (4) About 330 net lines (469 removed from text.zig) of first-slice text-pattern code were deleted: `TerminalTextSnapshot`, `TerminalTextMetadata`, `terminalTextMetadata`, `snapshotTerminalPlainText`, `snapshotTerminalVisiblePlainText`, `visibleRangeInDocument`, the line and UTF-16 offset builders, their nine tests, the `mod.zig` re-exports, `mod.handleGetObject` and `widgets.handleTerminalGetObject`. The live `WM_GETOBJECT` root branch in `win32.zig` is a different, caching function that creates its provider with `std.heap.page_allocator` on purpose (a COM client can hold the provider past Host teardown), so it was not routed through anything. `com.SupportedTextSelection_Multiple` stays: it completes the SDK enum next to `_None` and `_Single`, which are used. (5) Harness: every process of the run was started with `CreateProcessW` and an explicit `lpDesktop = WinSta0\<desktop>`, and the driver checked each window's desktop by name (`GetThreadDesktop` + `GetUserObjectInformationW`, `UOI_NAME`) against its own before driving it; `Desktop-Of` as `-eq` on an `EnumWindows` list is not that check (it printed False for a window that was on the desktop). The test pane ran a non-interactive `pwsh -File` (no PSReadLine, so no history line), and the PSReadLine history file's size and mtime and `startup-attempts.json`'s hash and mtime were unchanged around every batch.
- 2026-10-15: Tab list UIA events, background-tab prompts and the undo-off banner (SMALL-04 A; follows CLOSE-01 and PKG-25). (1) A tab joining the strip raised no UIA structure event, so a reader's tab list went stale for every add path. They all end in one place: `syncTabButtons` makes the button (new tab, new window and its clones, session restore, undo of a close, a tab moved in, a rolled-back close), so it raises `children_invalidated` on the host's root once per pass that created a button, after the layout, or from an `errdefer` when the pass fails after making one (`notifyTabListUiaChanged`, renamed from `notifyTabRemovedUia`, which still serves every removal site and the failed-`Surface.init` rollback that destroys a button a reader was told about). Raising at each `tabs.insert` would have fired before the button exists, since a same-host tab gets its button from the next activation's chrome pass. A hidden strip stays silent, as for selection. Measured on a hidden desktop with a portable Debug copy, a Windows PowerShell 5.1 `-MTA` client subscribed with `AddStructureChangedEventHandler(host, Subtree)`: new tab twice, close_tab:this, undo gave `ChildrenInvalidated` 0, 0, 1, 0 before and 1, 1, 1, 1 after (UIA also delivers a few `ChildAdded` for the new elements, before and after). The unit test needs real chrome children: the `BannerTestWindow` fixture and a private desktop, with child windows for the surfaces because layout repaints the active panes (a surface without one logs `NoWindow`, an error-level log, and fails the test). (2) `close_tab:this` for a tab that is not in front (the tab X, a middle click, Delete on its button) with `undo-timeout = 0` asked "Close this tab?", which says nothing about which. `askBeforeClosing` now words the `.this_tab` prompt for such a tab as the OSC 52 prompt words its tab: title `Close tab 2?`, body `A process is still running in Tab 2 (vim). Closing that tab will terminate it, and undo is off.`, through `labels.promptTabName` (the one place that cuts the title to 24 cells and code points and replaces controls and bidi formatting), now shared by both prompts. The other prompts: the OSC 52 prompts already name the tab; the other-tabs and right-tabs prompts run from the tab in front (a tab's context menu selects the tab it opens on); window and quit prompts have no tab. `Surface.close`'s "Close this terminal?" usually runs from the key in front, but a read-only terminal closes itself when its program exits and asks first (core `needsConfirmQuit` answers true for read-only before it looks at `child_exited`), in whichever tab it is, so it names a tab behind too (`Close terminal in tab 2?`, `Host.nameBackgroundTerminal`). That is almost always after the program has exited, so its body says so ("The program in Tab 2 (vim) has exited. Read-only mode makes closing that terminal ask first.", from `child_exited`) and says a process is running only if one is; the plain prompt for the front terminal still says "A process is still running" in the same read-only case (left). The front tab and front terminal keep their wording. A review found that case; `askBeforeClosing` takes the Surface as `userdata` for `.this_tab` (documented on `CloseScope`). (3) The banner after the last tab closes said "Use undo to restore it." (or named the undo key) with `undo-timeout = 0`, where the prune timer takes the entry at once. `tabClosedMessage` takes `undo_available` and says "Tab closed." then; `App.undoOff` is the one test for exactly 0, shared with the ask-first rule (a 1 ms timeout still offers it and still does not ask). Harness traps measured on the way: a `-Dtest-filter` value with spaces reaches `zig build` as several arguments and matches nothing (69 passed, 1 skipped is the no-match baseline), so use one token; a window launched with `STARTUPINFO.wShowWindow = SW_HIDE` stays hidden, and a child's `IsWindowVisible` is then false, so launch with `SW_SHOWNOACTIVATE` (4) on the private desktop; reading a control's text in another process needs `WM_GETTEXT` (`SendMessageTimeout`), not `GetWindowText`.
- 2026-04-16: Win32 UIA providers live under `src/apprt/win32_uia/`. `RootProvider` is a reference-counted `IRawElementProviderSimple`; `QueryInterface` must `AddRef` on success. Every PR that adds a new UI widget must add a matching provider — retrofitting accessibility is where accessibility debt lives.
- 2026-04-16: The Win32 UIA `VARIANT` mirror in `win32_uia/com.zig` must match the Windows ABI: 24 bytes on 64-bit and 16 on 32-bit (an 8-byte header plus a payload union two pointers wide). A comptime assertion and the test "VARIANT matches Windows ABI layout" guard this; do not disable either, and do not widen the union past two pointers.
- 2026-04-16: `win32_uia/events.zig` is the canonical path for every UIA event raise — every widget that gains / loses focus, adds / removes children, or mutates a notifiable property routes through there. The helpers short-circuit on `UiaClientsAreListening() == FALSE` so the idle "no screen reader attached" path stays cheap. Raising events directly via `uiautomationcore` in new code is a bug.
- 2026-04-16: BSTR ownership in UIA `GetPropertyValue`: the caller (UIA framework on behalf of Narrator/NVDA/Inspect) frees each returned BSTR via `VariantClear → SysFreeString`. Provider implementations MUST allocate a fresh BSTR per call. Caching a `SysAllocString` pointer and handing it back a second time produces a use-after-free on the second query and a double-free when the provider tries to free its "cached" copy on teardown. `RootProvider` now carries no cached BSTR state — `allocBstrFromLiteral` and `allocNameBstr` allocate per-call.
- 2026-04-16: `UIA_NamePropertyId` on the `RootProvider` reads the live HWND title via `GetWindowTextLengthW` + `GetWindowTextW`, not a literal "noctty" fallback, so screen readers announce the current window title (including post-rename). Fallback to "noctty" only fires on `GetWindowTextLengthW <= 0` or allocation failure. Re-announcing on title change requires raising `UiaRaiseAutomationPropertyChangedEvent` at the call site — not in the provider.
- 2026-04-16: `src/apprt/win32_uia/widgets.zig` hosts per-widget UIA providers. `PaletteListProvider` implements the minimum surface (IUnknown + IRawElementProviderSimple + ControlType=List + live Name) and is created fresh per WM_GETOBJECT query via `handlePaletteListGetObject`. The `PaletteListState` indirection decouples the provider from `Host` to keep the module cycle-free; `paletteListNameThunk` casts the void-pointer back to `*const Host`. `Host.buildPaletteListName` produces strings like "Command palette, 3 of 87: New Tab — new_tab" so Narrator announces the selected entry when the list is inspected. Selection-change `UIA_NamePropertyId` events need a stable provider instance to target; per-row `IRawElementProviderFragment` + `IInvokeProvider` item providers are not exposed by this provider.
