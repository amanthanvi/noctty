- 2026-10-31: The Win32 facade's dependency bags and forwarding aliases only grew, because a forwarder always compiles and nothing counted them. Each extraction from R03 to R06a (#584 to #590) left a `pub const <module>_runtime = .{ ... }` bag on `src/apprt/win32.zig` for its module, and later work added entries to them. A bag breaks no cycle (Zig allows import cycles) and hides nothing: of its 391 production entries, about 120 forward leaf modules any file can import itself and 62 forward `labels` names. `src/apprt/win32/facade_budget.zig` (test-only, no pub declarations, reached from `win32.zig`'s root `test {}` block) started from what was measured on 21d28e459: the 17 bags (the 16 `*_runtime` bags, 391 production and 50 test entries, plus `test_support_runtime`, the 55 fixture bindings that were an anonymous literal in the `Fixtures(...)` call and are still passed to the one instantiation the 2026-10-25 R00 entry in test-harnesses.md requires), 575 pub declarations on the facade (574 plus `test_support_runtime`), 322 forwarding aliases and 10 `win32.App` fields named `test_*`. Moving the child-control plumbing to `win32/child_window.zig` (the first `leaves` row) and the owned-string helpers to `win32/text.zig` took 44 production entries, 1 test entry and 3 fixture bindings out of the bags and 17 pub declarations and 4 aliases off the facade; the guard's rows, not these figures, are the current budget. Traps measured while writing it. (1) Count aliases with `std.zig.Ast` (a root var declaration whose init node is `.field_access`), not with a line regex: the design's 307 was the untyped `const x = a.b;` lines and missed 11 typed metric aliases (`pub const host_overlay_height: i32 = default_metrics.height_overlay;`), a twelfth with a trailing comment and 3 `@import("...").X` forms. (2) An `inline for` over the facade's 575 declarations with comptime string compares exceeds Zig's default 1000 backwards branches (`evaluation exceeded 1000 backwards branches`); the guard raises `@setEvalBranchQuota`. (3) A mutant that adds `const x = std.mem;` to the facade never reaches the guard: Zig rejects a container-level `x` that a local `x` anywhere in the file shadows (`local constant shadows declaration of 'x'`), so give a mutant a name the file does not use. (4) Comptime cannot list files, and a test that drops out of the graph fails nothing, so the file-set half of the rule is in `test/windows/flagship/contracts/Contracts.20-Zig.ps1`: the guard's root line and a floor of 2 tests, the exact set of `src/apprt` files that reach `win32.zig` (the guard and the 15 importers it started with; a file reaches it by importing it, or through `src/apprt.zig`'s re-exports `apprt.win32` and `apprt.runtime`) and `*_runtime` bags declared only in `win32.zig`. The local full suite does not run that file: run `test/windows/flagship/Test-VerificationContracts.ps1`, or rely on CI's Windows Checks. (5) `@typeInfo(win32)` lists only pub declarations, so a private bag (one a generic such as `Fixtures` takes as an argument) escapes it; the guard also reads the facade's root declarations with `std.zig.Ast` and fails a private `*_runtime` with `NewDependencyBag`. The contract's patterns accept a type annotation (`const apprt: type = @import(...)`, `const extra_runtime: T = .{`), which a pattern requiring `=` right after the name let through (all three found in review, each shown passing before the fix and failing after). Each of the guard's errors (`NewDependencyBag`, `FacadeBudgetExceeded`, `FacadeBudgetStale`, `LeafImportsFacade`, `LeafSurfaceGrew`) and each contract check failed under a mutant before a pass was trusted. Rule: add no `*_runtime` bag, bag entry or facade alias; import each name from the module that owns it, and use facade-only objects (`App`, `Host`, `Surface`, `Tab`, the window procedures, UIA thunks, `test_support`) as `win32.X`. The budget is exact both ways: a change that removes a bag entry, alias or pub declaration pastes the number the guard prints (it fails with `FacadeBudgetStale` until then), a change that rewrites a module's role deletes that module's whole bag, and raising a row needs a `// why:` on that row. A new leaf module under `win32/` gets a row in the guard's `leaves` table with its pub-declaration count and imports none of `../win32.zig`, `app.zig`, `host.zig`, `terminal_window.zig` and `../../apprt.zig` (which re-exports the facade; take an `apprt` type from the file that owns it, such as `../action.zig`). The guard checks a leaf's own imports, not what they import in turn. This qualifies the R06a and R06c entries below: their bindings keep their declaration identity, and their counts are now the guard's rows.

- 2026-05-01: In Zig Win32 FFI, `std.os.windows.HANDLE` is non-null; APIs like `CreateJobObjectW` that signal failure with `NULL` must use `?HANDLE` in extern declarations or future callers cannot model failure correctly.
