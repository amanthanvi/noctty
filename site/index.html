Built for long sessions

What Noctty does well

The terminal core comes from Ghostty. The Windows application around it — windowing, session handling, settings, and the updater — is this project's own work, written for how Windows actually behaves.

Session restoration

Close Noctty and open it again to the same windows, tabs, and split layout. Working directories, profiles, and explicit titles come back with them, so a restart costs you the reopen, not the rebuild.

  • Layout, working directories, and titles restore on launch
  • Per-profile shells: PowerShell, cmd, Git Bash, opt-in WSL
  • Pane contents return as clearly-marked snapshots

Universal palette

One shortcut, then a few characters, reaches anything: an action, a tab, a pane, a profile, a theme, or a setting. Fuzzy matching means you type what you remember rather than where it lives.

  • Actions, tabs, panes, profiles, themes, and settings in one list
  • Keyboard-first, with every entry reachable without the mouse

Native settings

A real settings window covers appearance, shells, keybindings, privacy, and updates. Changes are staged and then written without rewriting the unrelated lines of your config file.

  • Edits stay surgical: your comments and ordering survive
  • Config lives at %LOCALAPPDATA%\noctty\config.ghostty
  • Updates are checked, verified, then applied when you say so

Honest about the parts

How it's built

Ghostty's core, a Windows application

Ghostty does not ship a Windows app today, so Noctty builds one around Ghostty's terminal core. Parsing, fonts, rendering, input, and shell integration are shared with upstream and track it closely.

The Win32 runtime, windowing, tab and split management, the settings window, and the updater are this fork's own work. Noctty is an independent project and is not affiliated with the Ghostty non-profit.

What to expect

Public releases run on Windows 10 and 11 for x64 and ARM64, with Authenticode-signed installers and binaries. The project moves quickly, so the release notes are worth reading before you update.

There is no telemetry and there are no analytics. The only network traffic is the update check against GitHub Releases, and an update is staged only after its signature and checksum verify — then it waits for you.

Accessibility is partial, not complete. Terminal text, focus, selection, the command palette, and native settings controls have UI Automation coverage today. Broader per-widget and screen-reader validation is still in progress.
